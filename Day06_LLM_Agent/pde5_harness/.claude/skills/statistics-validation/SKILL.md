# statistics-validation

## 핵심 원칙

**수식이 틀리면 그 위의 결론은 전부 무의미하다.** 그런데 통계 함수의 버그는 조용하다 —
그럴듯한 숫자가 나오고, 게이트도 통과하고, 그림도 그려진다.

특히 위험한 것이 **동점 처리**다. 도킹 점수에는 동점이 많다. 단순 정렬 순위로 Spearman 을
계산하면 평균 순위를 쓸 때와 값이 달라지고, 그 차이가 p 값의 유의성 판정을 뒤집을 수 있다.
이 하네스는 실제로 그 버그를 냈다 (-0.498 로 보고했으나 올바른 값은 -0.474).

## 어떻게

```bash
python scripts/test_statistics.py
```

무작위 데이터에 **동점을 의도적으로 주입**해 참조 구현과 대조한다.

| 내 함수 | 참조 | 허용 편차 |
|---------|------|-----------|
| `spearman` | `scipy.stats.spearmanr` | 1e-9 |
| `partial_spearman` | `rankdata` 잔차의 `pearsonr` | 1e-8 |
| `auc` | `scipy.stats.mannwhitneyu` / (n₁n₂) | 1e-9 |
| `fisher_ci` | 해석해 `tanh(z ± 1.96/√(n-3))` | 정확 일치 |
| `sdf_models` (다중 모델 파서) | `rdkit.Chem.SDMolSupplier` | 모델 수·중원자 수·좌표 1e-3 |

**파서도 같은 위험을 진다.** 손으로 짠 SDF 파서가 모델 경계를 잘못 잡으면 엉뚱한 자세의
좌표로 접촉을 계산하고, 그래도 그럴듯한 잔기 목록이 나온다. 좌표까지 대조해야 한다.

## 언제 발동하는가

- 통계 함수를 새로 구현하거나 수정했을 때
- 외부 의존을 줄이려고 `scipy` 대신 직접 짰을 때
- 리뷰어가 수치를 독립 재계산해 불일치를 지적했을 때

## 하지 말 것

- "간단한 수식이라 맞을 것" 으로 넘어가기
- 동점 없는 데이터로만 검정하기 (실제 데이터에는 동점이 있다)
- 참조 구현과 다른 값이 나왔는데 "정의가 다르다" 로 설명하고 넘어가기 —
  정의가 다르면 어느 정의를 쓰는지 보고서에 적어야 한다
