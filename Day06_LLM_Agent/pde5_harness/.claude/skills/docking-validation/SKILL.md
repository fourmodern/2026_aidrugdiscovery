# docking-validation

## 핵심 원칙
**대조 없는 도킹 점수는 해석할 수 없다.** 도킹이 성립하려면 두 가지가 따로 참이어야 한다.

- **자세 생성** — 프로그램이 실제 결합 자세를 만들어낼 수 있는가
- **채점** — 그 자세에 매기는 점수가 실측 친화도와 같은 방향인가

둘은 독립이며, 전자가 성립해도 후자는 실패할 수 있다. 대조를 나누지 않으면 어느 쪽이
실패했는지 알 수 없고, 처방도 달라진다 (전자는 탐색 강화, 후자는 점수 교체).

## 어떻게
```bash
python scripts/dock_actives.py --exhaustiveness 16 --seed 42 --data sample_run/dataset30.json
```

## 두 대조
| 대조 | 측정 | 실패하면 |
|------|------|----------|
| C1 샘플링 | 상위 모드 중 결정 자세 대비 최선 RMSD | 도킹 자체를 진행할 수 없다 |
| C2 채점 | 1위 자세의 RMSD | 점수 기반 순위를 신뢰할 수 없다 |

기준은 관례적으로 2.0 Å. C1 은 게이트이고 **C2 는 해석 제약**이다. C2 가 실패하면
자세 선택을 점수가 아니라 참조 리간드와의 MCS-RMSD 로 하고 그 사실을 방법에 명시한다.

## 하드 규칙
- 도킹 점수는 **가설**이며 결합 친화도의 실측이 아니다
- 대조 결과를 보고서에서 빼지 않는다. 실패했으면 실패했다고 적는다
- 시드와 exhaustiveness 를 기록한다
