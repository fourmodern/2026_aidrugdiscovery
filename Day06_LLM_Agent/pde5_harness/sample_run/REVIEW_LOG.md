### 리뷰어가 찾아낸 하네스 자체의 결함

보고서가 아니라 **심사 대상이 의존하는 코드**에서 나온 결함이다.

1. **`run_harness.py` 가 selectivity 게이트의 반환값을 버렸다.**
   앞 세 단계는 `if env is None or not gate(...): return 1` 인데 네 번째만
   `if env is not None: gate(...)` 였다. 실패해도 다음 단계가 그대로 진행된다.

2. **`selectivity.py` 의 검사 4개가 전부 모듈 리터럴 상수를 읽었다.**
   어떤 입력을 주어도 FAIL 이 날 수 없는 항진명제였다.
   실증: `--smiles "NOT_A_MOLECULE_@@@"` 로도 `passed=True`.
   따라서 그 단계의 `PASSED` 한 줄은 정보량이 0이다.

3. **`verify.py` 의 `gate()` docstring 이 구현과 모순.**
   "비정상 종료"라고 적었으나 `raise` 도 `sys.exit` 도 없이 bool 만 반환한다.

4. **계약이 규정한 다섯 번째 게이트가 실행되지 않았다.**
   `numbers_backed()` 는 실행 코드에 호출자가 0곳인 dead code 였다.

5. **훅 2종은 비차단이다.** 두 훅 모두 모든 경로에서 `exit 0` 이며 CLI 실행에서는
   발화조차 하지 않는다. 그런데 보고서 표에는 "규약을 기계가 강제"라고 적혀 있었다.

### 보고서의 사실 오류

- "게이트 4개가 모두 차단한다" — 실제로는 3개만.
- "10건 전부 Lipinski 통과 → 위반이 드물다" — **10건 중 7건이 MW 500 초과**.
  Ro5 가 걸러내지 못한 이유는 게이트가 위반 1개를 허용하기 때문이었다.
- "모든 수치를 스크립트가 주입, 사람이 타이핑하지 않는다" — 스킬 수 "(6종)" 등
  일부는 손으로 적었고, 그중 스킬 수는 **실제 11개로 틀린 값**이었다.

## 조치

**코드**
- selectivity 게이트가 반환값을 검사하도록 수정
- selectivity 검사를 입력 의존으로 교체 (산출물 전수 스캔 + 입력 SMILES 파싱).
  수정 후 쓰레기 SMILES 에 대해 `passed=False` 확인

- QED 임계 민감도 스윕 (0.35~0.70)

**보고서**
- 제목·초록·결론에서 비교 주장 철회 (대조군 없음)
- 강제력 실사 표 신설, Lipinski 해석 정정, 경쟁 가설 H2/H3/H4 명시
- 화합물 ChEMBL ID 표기, 참고문헌 19건 (Crossref/NCBI API 로 실재 검증)
- 라이선스·오남용(dual-use)·이해상충 절 추가
- 무-날조 선언의 적용 범위를 "결과 수치"로 정확히 좁힘

## 이 사이클에서 배운 것

1. **게이트 통과 로그는 강제의 증거가 아니다.** 실패가 관측 불가능한 게이트의 통과는
   정보량이 0이다. 뮤테이션 테스팅이 같은 이유로 결함을 심는다.
2. **본문을 고치면 그림과 슬라이드도 고쳐야 한다.** 세 차례 연속으로 부속 산출물이
   본문이 철회한 주장을 담고 있었다. 학생이 실제로 보는 것은 슬라이드다.
3. **절차를 넣었다고 말하려면 코드가 있어야 한다.** "검사를 넣었다", "기계로 캡처했다" 는
   주장이 두 번 근거 없이 나왔고 두 번 다 리뷰에서 걸렸다.
